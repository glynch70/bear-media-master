# Dependency, spam and mobile performance follow-up

## Dependency cleanup

Removed the shadcn component-generator CLI from the installed dependency tree. Its only application import was its small Tailwind stylesheet. That stylesheet is preserved verbatim in `app/styles/component-variants.css`, with the upstream MIT licence alongside it. Components and generated UI remain unchanged; future generator use can use a reviewed one-off CLI invocation.

Refreshed vulnerable transitive development dependencies within their declared constraints, including brace-expansion, js-yaml, source-map-js and zod. No runtime framework upgrade or new production dependency was introduced.

Audit reduced from 55 advisories (including one critical and 28 high) to one moderate development-only minimatch advisory. Its dependency is under the TypeScript ESLint parser and currently declares minimatch 10; the reported fix requires 11. Retained the upstream supported major rather than forcing an incompatible override. It concerns resource exhaustion from crafted glob input during tooling execution; this package is not exposed through the website's public form. Production audit remains zero advisories.

## Enquiry and spam check

A read-only search of connected email for form notifications over the previous 30 days found six notifications: four tests, one apparent business enquiry and one unsolicited sales approach. This is a limited mailbox observation, not a count of rejected bot attempts or a guarantee that every mailbox message is represented. It does not justify adding a database or paid global rate limiter at present.

The 14 November production test notification and confirmation both arrived in the connected inbox. This supersedes the earlier audit's outstanding normal-browser delivery check. No further test email was sent.

Monitoring approach: periodically review form notifications and any delivery failures. Revisit shared rate limiting if repeated automated submissions get through Turnstile, hourly bursts reach the inbox, or delivery-provider usage rises unexpectedly. Keep legitimate enquiry details out of analytics. No inbox labels, messages, forwarding rules or recurring automations were changed; no scheduled monitoring has been enabled.

## Mobile performance baseline

Run 1 accessibility, best practices and SEO: 100 each. These automated checks do not replace manual accessibility testing or field measurements. INP is a field metric and is not established by these runs. CPU/network characteristics and cache conditions affect lab scores.

The baseline identified oversized responsive candidates for small bento tiles. Changed their declared width from 36vw to 30vw, matching the actual roughly 30vw grid columns. No source image quality or crops changed. The dominant image keeps its separate size hint and high fetch priority; mobile hero video remains disabled. Post-deployment measurements are reported in the completion message.
